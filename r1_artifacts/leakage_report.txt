ADJACENT-FRAME LEAKAGE ANALYSIS
============================================================

Dataset: UAV-PDD2023 (Zenodo record 8429208)
Total original images: 2,440
Split: 70% train (1,707) / 20% val (489) / 10% test (244)
Random seed: 42

METHOD:
Each original UAV image (5,184x3,888) was tiled into 4 patches
(top_right, bottom_right, top_left, bottom_left) before annotation.
The 5-digit number in the filename identifies the source image:
  e.g., lr_00001_top_right.jpg → source image #1

PIXEL-LEVEL LEAKAGE: NONE
All four patches of a given source image always appear in the same split,
thus avoiding exact image overlap across train/val/test.

ADJACENT-FRAME PROXIMITY:
Consecutive sequence numbers (n, n+1) likely represent consecutive UAV
frames along the flight trajectory, capturing overlapping road segments.
The random split does not guarantee that adjacent sequences stay in the
same split.

POTENTIAL IMPACT:
- Some test images may have adjacent-frame neighbors in the training set
- This is NOT pixel-level leakage, but represents spatial proximity
- This approximates a realistic generalization scenario: the model must
  detect distresses on road segments it has not directly seen during
  training, even if spatially proximate segments appear in training data

MITIGATION (for future work):
- Stratify the split by source-image sequence ranges (e.g., assign
  contiguous blocks of sequences to each split)
- Use k-fold cross-validation with sequence-block-aware folds
- Report performance on spatially distant test segments as a separate
  out-of-domain evaluation

NOTE:
This analysis was performed after the split was generated.
The split used for all reported results remains unchanged.
